給新站長的完整開站手冊

把這個網站變成你的，從零開始

這是一份「照著做就會成功」的說明書。給完全沒有工程背景的人。每一步都告訴你按哪裡、貼什麼。

🗣️ 白話講解 📋 逐步照做 ⏱️ 分幾天完成 🖨️ 可列印

👋 先看這裡（30 秒）

這個網站可以：賣線上課程、賣數位檔案、收月費會員、刷卡收錢、寄通知信、放防盜影片。你會有一個專屬的「後台」，之後上架課程、看訂單都在那裡點一點就好。

架設要用到 6 個免費服務（像積木一樣拼起來）。全部弄好大約要花 3～5 小時，但不是一次做完——中間有幾關要「等別人審核」，所以請分幾天做，不要趕。

⏳ 老實話：有 3 個地方一定要等，這不是你的問題

再詳細的說明書也跳不過這 3 關，因為它們是「別人要處理」的事。看到 要等 / 要幫忙 標記就是這種關卡：

  • 刷卡收錢（PayUni）：要送件給金流公司審核你的商家資格，通常等 幾個工作天。建議第一天就先去送件，一邊等一邊做其他步驟。
  • 用自己的網址寄信：要改網域設定並等它生效（幾分鐘到幾小時）。先用系統預設的也能動。
  • 每日自動備份到 Google Drive（步驟 9B）：這步比較技術，建議找懂電腦的人幫你用一次就好，之後全自動。（注意：步驟 9A 的「保活」不難、請務必自己做。）
這份手冊的順序
  1. 開始前：準備什麼
  2. 申請 6 個帳號（含馬上送 PayUni 審核）
  3. 建立資料庫（Supabase）
  4. 設定影片（Bunny）
  5. 設定寄信（Resend）
  6. 設定刷卡（PayUni）
  7. 把網站放上線（Netlify）
  8. 建立你的管理員帳號
  9. 開門收客前的安全檢查（很重要）
  10. 開啟保活（必做）＋自動備份（選配）
  11. 上線後的日常操作

名詞先講清楚

只有 2 個詞要記住

你會看到的詞白話意思
環境變數
（Environment Variables）		就是一堆「設定值」，像帳號密碼。你要把它們貼到網站平台的設定欄位裡，網站才知道怎麼連到資料庫、怎麼收錢。本手冊會告訴你每一個去哪拿、貼到哪。
金鑰 / Key一長串英文數字，等於「通行密碼」。看到寫「機密 / secret」的絕對不能給別人、不能貼到公開的地方。

步驟 0

0

開始前，準備這些

約 10 分鐘

  • 一台電腦（Windows 或 Mac 都可以）與網路。
  • 一個常用的電子信箱（用來註冊下面的服務）。
  • 賣方交給你的東西：這個網站的程式碼（通常是一個 GitHub 連結或一個壓縮檔），以及賣方原本填好的一份設定清單（檔名 .env.example 或 .env.local）。
  • 如果你要用自己的網址（例如 yourschool.com）：先準備好，或之後用平台送的免費網址也行。
  • 刷卡收錢會用到公司/商號的營業登記（PayUni 審核要）。個人也可問 PayUni 可否申請。

先把 6 個免費帳號都申請好。點下面連結 → 用信箱註冊 → 收信點驗證即可。

Supabase資料庫＝記住會員、訂單、課程的地方。

步驟 2

2

建立資料庫（Supabase）

約 40 分鐘　這步最多字，但每個動作都很簡單

2-1. 建立專案

  1. 登入 Supabase → 按 New project（新專案）。
  2. 取一個名字、選最近的區域（例如 Singapore）。
  3. 它會要你設一組資料庫密碼。請把這組密碼抄下來存好（之後備份會用到）。
  4. 按建立，等它跑好（約 1～2 分鐘）。

2-2. 建立資料表（把「空櫃子」擺好）

左側點 SQL Editor → New query。接下來要把程式碼裡 db/ 資料夾中的檔案，一個一個整份貼進去、各按一次 Run（右下角綠色按鈕）。順序很重要，照下面來：

依序貼上並各按 Run（每個都開一個 New query）
1.  db/init.sql                  ← 建立所有櫃子＋範例資料
2.  db/add_auth_flows.sql        ← 信箱驗證、忘記密碼
3.  db/add_rate_limiting.sql     ← 防止被灌爆的保護
4.  db/add_performance_indexes.sql ← 讓網站更快（可選但建議）
5.  db/enable_rls.sql            ← 最後跑！打開資料保護鎖

⚠️ 第 5 個一定要放最後

enable_rls.sql 是「上鎖」的動作。一定要等前面都跑完、再跑它。跑完看到 Success. No rows returned 就對了。

💡 想更省事？（給願意開一次終端機的人）

賣方或工程師可以在電腦上跑一行指令 npm run setup -- --migrate，自動把上面 5 個檔一次跑完（此法需先在 .env.local 設定 SUPABASE_DB_URL 連線字串）。做不到就用上面的手動貼上法，一樣的結果。

2-3. 拿 3 把鑰匙（等一下要貼到上線平台）

點 Supabase 畫面最上方的 Connect 按鈕（把所有金鑰放在同一個視窗，最好找）。抄下這 3 個：

① 專案網址Connect 視窗 → App Frameworks
NEXT_PUBLIC_SUPABASE_URL
② 公開金鑰（給瀏覽器用，新版叫 Publishable key）同上視窗
NEXT_PUBLIC_SUPABASE_ANON_KEY
③ 機密金鑰 ⚠️ 絕不外洩（新版 Secret key / 舊版 service_role）Connect → Secret / Legacy API Keys
SUPABASE_SERVICE_ROLE_KEY

（順手也複製一份「連線字串 Connection string / URI」，把裡面的 [YOUR-PASSWORD] 換成 2-1 設的密碼——步驟 9 備份會用到。現在用不到可先跳過。）

2-4. 建立圖片儲存空間

  1. 左側點 Storage → New bucket。
  2. 名字打 uploads，勾選 Public，建立。

✅ 完成後你會有

一個裝好所有資料表的資料庫、3 把鑰匙抄在手邊、一個 uploads 圖片空間。

步驟 3

3

設定影片（Bunny.net）

約 20 分鐘　沒有課程影片的話可先跳過，之後再補

  1. Bunny → Stream → 建一個 Video Library（影片庫）。
  2. 進這個影片庫的 Security 分頁，打開 Embed View Token Authentication（這就是「防盜開關」，一定要打開防盜才會生效）。
  3. 抄下這 3 個值：
① 影片庫 ID（一串數字）影片庫 → API 分頁
BUNNY_STREAM_LIBRARY_ID
② 防盜金鑰 ⚠️ 機密（播放防盜用）影片庫 → Security 分頁
BUNNY_TOKEN_AUTH_KEY
③ 上傳用 API 金鑰 ⚠️ 機密（批次上傳影片才需要）影片庫 → API 分頁的 AccessKey
BUNNY_STREAM_API_KEY

💡 ② 和 ③ 是不同的兩把鑰匙

② 在 Security 分頁（給播放防盜用）；③ 在 API 分頁（給《搬家手冊》批次上傳影片用）。名字很像，別搞混或以為填過了。

之後在後台新增課程章節時，「影片網址」欄位貼該影片的網址或編號，系統會自動加防盜。

步驟 4

4

設定寄信（Resend）

約 15 分鐘

  1. Resend → 左側 API Keys → Create，複製那把鑰匙。
  2. 驗證你的網域（左側 Domains）→ 之後把寄件人設成 no-reply@你的網址。對外收客前必做

⚠️ 這步不能跳過，否則新客戶會「註冊了卻無法登入」

新客戶註冊後，系統會寄一封「驗證信」，客戶要點了才能登入。若寄件人還用預設的沙盒地址 onboarding@resend.dev，Resend 只會把信寄到你自己、真正的客戶永遠收不到驗證信 → 就登不進去、買了也用不了。購買通知信、忘記密碼信也一樣收不到。

所以：正式對外收客前，一定要驗證自家網域、把寄件人換成 no-reply@你的網址。（驗證要改網域 DNS、等它生效，早點做。）

寄信鑰匙Resend → API Keys
RESEND_API_KEY
寄件人信箱（驗證網域後填這個；正式站務必用自家網域）
RESEND_FROM_EMAIL = no-reply@你的網址
測試收件信箱（網域還沒驗證好、想先測試時填你自己的信箱）用沙盒寄件人時，信只會寄到這裡
RESEND_TEST_RECIPIENT = 你自己的信箱@example.com
聯絡表單的收件信箱（填你自己的客服信箱）
CONTACT_TO_EMAIL = 你的客服信箱@example.com

💡 還在等網域驗證時怎麼先測？

可暫時 RESEND_FROM_EMAIL = onboarding@resend.dev 並填上面的 RESEND_TEST_RECIPIENT，此時所有信只會寄到你自己的信箱（方便看信長怎樣）。但這只是測試用，對外收客前務必換成自家網域。

步驟 5

5

設定刷卡（PayUni）

審核通過後約 10 分鐘 要等審核

等步驟 1 送的商家審核通過後，回來做這步。

  1. 登入 PayUni 後台 → 會員 → 商店清單 → 點 SHOP 開頭的商店 → 串接設定 → 《API 串接金鑰》。
  2. 抄下 3 個值（測試階段先用 Sandbox 測試那組）。
商店代號、加密金鑰、加密向量PayUni → API 串接金鑰
PAYUNI_MERID       = 你的商店代號
PAYUNI_HASH_KEY    = 你的 HashKey
PAYUNI_HASH_IV     = 你的 HashIV
付款頁網址（測試先用 sandbox，正式上線再換）
# 測試階段：
NEXT_PUBLIC_PAYUNI_UPP_URL = https://sandbox-api.payuni.com.tw/api/upp
# 正式收真錢時改成：
# NEXT_PUBLIC_PAYUNI_UPP_URL = https://api.payuni.com.tw/api/upp
NEXT_PUBLIC_PAYUNI_MERID   = 你的商店代號（同上）

💡 不用手動填回呼網址

系統送出付款時會自動帶上回呼網址。若 PayUni 後台有 Notify URL 欄位要你填，就填 https://你的網址/api/webhook/payuni（網址等步驟 6 上線後才會有）。

步驟 6

6

把網站放上線（Netlify）

約 30 分鐘　這步做完就有一個能開的網址了

6-1. 讓程式碼進到你的 GitHub

請賣方把專案轉移或複製到你的 GitHub 帳號底下（最簡單：賣方在 GitHub repo 的 Settings → Transfer 轉給你）。轉好後你的 GitHub 就會有一個 bds-web 之類的倉庫。

6-2. 匯入到 Netlify

  1. Netlify → Add new project → Import an existing project。
  2. 選 GitHub → 授權 → 選你的那個倉庫。
  3. 先不要急著按 Deploy，先做下面 6-3 填設定。

6-3. 把所有鑰匙貼進去

進 Project configuration → Environment variables。把前面各步驟抄下的值全部加進來（有「Import from a .env file」可整份貼更快）。完整清單如下：

要貼的全部設定（左邊名字、右邊你的值）
# --- 網站基本 ---
NEXTAUTH_URL              = （先貼 Netlify 給你的網址，綁自己網域後再改）
NEXTAUTH_SECRET           = （見下方「怎麼產生」）

# --- 資料庫 Supabase（步驟 2）---
NEXT_PUBLIC_SUPABASE_URL       = ...
NEXT_PUBLIC_SUPABASE_ANON_KEY  = ...
SUPABASE_SERVICE_ROLE_KEY      = ...

# --- 刷卡 PayUni（步驟 5）---
PAYUNI_MERID               = ...
PAYUNI_HASH_KEY            = ...
PAYUNI_HASH_IV             = ...
NEXT_PUBLIC_PAYUNI_UPP_URL = https://sandbox-api.payuni.com.tw/api/upp
NEXT_PUBLIC_PAYUNI_MERID   = ...

# --- 影片 Bunny（步驟 3）---
BUNNY_STREAM_LIBRARY_ID    = ...
BUNNY_TOKEN_AUTH_KEY       = ...   # 播放防盜用
BUNNY_STREAM_API_KEY       = ...   # 影片批次上傳用（另一把，見步驟 3）

# --- 寄信 Resend（步驟 4）---
RESEND_API_KEY             = ...
RESEND_FROM_EMAIL          = no-reply@你的網址   # 正式收客務必用自家已驗證網域
RESEND_TEST_RECIPIENT      = 你自己的信箱          # 網域還沒驗證好時的測試收件者
CONTACT_TO_EMAIL           = 你的客服信箱

# --- 安全開關（正式站務必是 false）---
ENABLE_PAYMENT_SIMULATION  = false

💡 NEXTAUTH_SECRET 怎麼產生？

它只是一段很長的隨機亂碼（網站拿來加密登入用）。最簡單：打開網頁 generate-secret.vercel.app/32，把畫面上那串複製貼上即可。

  1. 全部貼好後，按 Deploy（部署）。等幾分鐘。
  2. 完成後 Netlify 會給你一個網址（像 xxxx.netlify.app）。回到上面把 NEXTAUTH_URL 改成這個網址，再重新部署一次。
  3. （之後有自己網域）到 Domain management 綁定你的網址，再把 NEXTAUTH_URL 改成它、重新部署。

✅ 完成後你會有

一個可以打開的網站！先點進去看看首頁、課程頁有沒有正常顯示。

步驟 7

7

建立你的管理員帳號

約 5 分鐘

  1. 打開你的網站，網址後面加 /signup，用你的信箱註冊一個帳號。
  2. 回 Supabase → SQL Editor → New query，貼上下面這行（把信箱換成你剛註冊的），按 Run。它會把你變成管理員、同時免去信箱驗證：
把自己設為管理員（信箱記得換成你的）Supabase → SQL Editor
UPDATE users SET role = 'admin', is_verified = true
WHERE email = '你的信箱@example.com';
  1. 重新登入 → 右上角會出現「管理後台」→ 進入 /admin。大功告成！

步驟 8

8

開門收客前的安全檢查

約 20 分鐘　開始收真錢之前，這幾項一定要確認

  • 資料保護鎖有打開：確定步驟 2 的 db/enable_rls.sql 有跑過（最後一個）。
  • 安全開關關好：Netlify 設定裡 ENABLE_PAYMENT_SIMULATION 必須是 false（不然有人能免費開通會員）。
  • 金流換正式：確認商家審核通過後，把 NEXT_PUBLIC_PAYUNI_UPP_URL 換成正式端點、金鑰換成正式那組，重新部署。
  • 網址填對：NEXTAUTH_URL 已改成你真正的網址（不是預設的假網址）。
  • 寄信正常（很重要）：RESEND_FROM_EMAIL 已改成自家已驗證網域（不是 onboarding@resend.dev）。實測：用另一個信箱到 /signup 註冊 → 該信箱能收到「驗證信」→ 點了能成功登入。收不到＝客戶也會收不到、無法登入。
  • 真卡實測：用一張真卡買一筆最便宜的商品，確認「付款成功 → 自動開通 → 收到通知信」整條走得通，再退刷。
  • 換成你的品牌：後台「設定」把站名、Logo、主色、聯絡信箱、FAQ、公告改成你自己的；刪掉範例課程與範例訂單。
  • 保活已開：確認步驟 9A 的保活已設定並測試成功（否則網站閒置一週資料庫會睡著）。

💡 賣方已附一份「上線前清單」

專案裡有一個檔案 LAUNCH-CHECKLIST.md 與 GO-LIVE-TEST.md，是更完整的逐項打勾清單，上線前照著再走一遍最安心。

步驟 9

9A

開啟「保活」—— 這步請務必做

約 5 分鐘　很簡單，只是貼 2 個值

⚠️ 為什麼一定要做

免費版的資料庫約 7 天沒人使用就會「睡著」，睡著時客戶會遇到網站打不開或很慢。系統已內建一個「每 3 天自動戳一下」保持清醒的功能，但要你貼 2 個值它才會啟動。這步做完就一勞永逸、全自動。

  1. 到你的 GitHub 專案頁 → 上方 Settings（齒輪）→ 左側 Secrets and variables → Actions。
  2. 按綠色 New repository secret，新增第一個：
    Name 填這個
    SUPABASE_URL
    Value 貼你的專案網址（步驟 2 抄的那個）
    https://xxxx.supabase.co
  3. 再按一次 New repository secret，新增第二個：
    Name 填這個
    SUPABASE_ANON_KEY
    Value 貼你的公開金鑰（Publishable key，步驟 2 抄的）
    eyJ....（一長串）
  4. 到專案上方 Actions 分頁 → 左側點 「Supabase 保活（防免費版休眠）」 → 右側 Run workflow 跑一次測試。看到綠色打勾、日誌顯示 回應碼：200 就成功了。之後每 3 天自動跑，不用再管。

✅ 完成後

你的資料庫不會再因為沒人來而睡著，客戶隨時打開都順暢。

🗓️ 每兩個月要看一眼（GitHub 的規定）

GitHub 有個規則：如果這個專案連續約 60 天沒有任何變更，它會自動把「保活」「備份」這類排程停用（不會通知你）。停用後資料庫又會開始會睡著。
解法很簡單：每隔一兩個月登入 GitHub → Actions 分頁看一眼，若看到 workflow 被停用（有 Enable workflow 按鈕），按一下重新啟用即可。（或請幫你設定的工程師加一個自動保持活躍的小機制。）

9B

每日備份到 Google Drive（選配，進階）

約 30 分鐘 可晚點做／找人幫一次

設定每天自動備份你的資料庫。備份有兩層：一層存成 GitHub 的檔案（保留 90 天），一層另外存到你的 Google Drive。

⚠️ 備份不是「零設定就有」——要先貼 1 個值它才會跑

備份需要能連到資料庫的「連線字串」。請比照 9A，到 GitHub → Settings → Secrets and variables → Actions 再新增一個 secret：

Name 填這個
SUPABASE_DB_URL
Value 貼資料庫連線字串（把 [YOUR-PASSWORD] 換成步驟 2-1 的密碼）Supabase → Connect → Connection string (URI)
postgresql://postgres:你的密碼@db.xxxx.supabase.co:5432/postgres

設好後，到 Actions 分頁點 「每日資料庫備份」 → Run workflow 跑一次，看到綠色打勾、且在該次紀錄下方 Artifacts 出現 db-backup 檔，才代表備份真的有生效。沒設這個值的話，備份會失敗、你其實一份都沒有。

💡 Google Drive 那層可以晚點做（進階）

把備份「另存一份到 Google Drive」比較技術（要設 rclone），建議找懂電腦的人幫你設定一次，專案裡的 SETUP-GUIDE.md 步驟 8 有完整指令。只要上面的 SUPABASE_DB_URL 設好了，GitHub 檔案那層備份就已經在保護你了，Google Drive 是再加一層。

上線之後

日常操作超簡單（這部分才是你每天用的）

架設好之後，你不用再碰上面那些設定。每天只要登入網站、進 /admin 後台，點一點就能經營：

後台功能你可以做什麼
課程 / 章節新增課程、貼影片網址、上傳教材講義。
文章 / 活動 / 數位下載 / 會員方案上架與管理各種內容和商品。
成員管理學員、手動幫某人開通課程。
財務看訂單、看營收、匯出報表。
留言審核、回覆學員的提問。
頁面管理 / 設定改「關於我們」「聯絡我們」、站名、Logo、公告等。

🆘 卡住了怎麼辦？

技術性的步驟（2、6、9）如果自己弄不出來，可以請工程師幫你做「一次性」設定——設定好之後，上架課程、改內容這些日常事，你自己就能完全掌握。這份手冊也可以直接轉給幫你的人看。
