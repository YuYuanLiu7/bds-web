給新站長的完整開站手冊

把這個網站變成你的，從零開始

這是一份「照著做就會成功」的說明書。給完全沒有工程背景的人。每一步都告訴你按哪裡、貼什麼。

🗣️ 白話講解 📋 逐步照做 ⏱️ 分幾天完成 🖨️ 可列印

👋 先看這裡（30 秒）

這個網站可以：賣線上課程、賣數位檔案、收月費會員、刷卡收錢、寄通知信、放防盜影片。你會有一個專屬的「後台」，之後上架課程、看訂單都在那裡點一點就好。

架設要用到 6 個服務（像積木一樣拼起來，多數免費）。全部弄好大約要花 3～5 小時，但不是一次做完——中間有幾關要「等別人審核」，所以請分幾天做，不要趕。

※ 誠實說明：這 6 個大多有免費額度，但 Bunny（影片）依用量計費、需綁定付款方式（會依觀看/儲存量實際扣款），PayUni（金流）每筆交易收手續費。其餘（Supabase、Netlify、Resend、GitHub）在你的用量內通常免費。
想先抓 Bunny 每月大概多少、要儲值多少？用 Bunny 影片費用估算器 填幾個數字即可。

⏳ 老實話：有 3 個地方一定要等，這不是你的問題

再詳細的說明書也跳不過這 3 關，因為它們是「別人要處理」的事。看到 要等 / 要幫忙 標記就是這種關卡：

  • 刷卡收錢（PayUni）：要送件給金流公司審核你的商家資格，通常等 幾個工作天。建議第一天就先去送件，一邊等一邊做其他步驟。
  • 用自己的網址寄信：要改網域設定並等它生效（幾分鐘到幾小時）。先用系統預設的也能動。
  • 每日自動備份到 Google Drive（步驟 9B）：這步比較技術，建議找懂電腦的人幫你用一次就好，之後全自動。（注意：步驟 9A 的「保活」不難、請務必自己做。）

名詞先講清楚

只有 2 個詞要記住

你會看到的詞白話意思
環境變數
（Environment Variables）		就是一堆「設定值」，像帳號密碼。你要把它們貼到網站平台的設定欄位裡，網站才知道怎麼連到資料庫、怎麼收錢。本手冊會告訴你每一個去哪拿、貼到哪。
金鑰 / Key一長串英文數字，等於「通行密碼」。看到寫「機密 / secret」的絕對不能給別人、不能貼到公開的地方。

🧭 開始前，先懂兩件事（會讓你少卡很多）

① 網站的按鈕名稱可能跟這裡寫的不一樣。Supabase、Netlify、Resend 這些網站常常改版、換名字、甚至改成英文。請認「你要做的事」而不是死記按鈕名字——例如要找「API 金鑰」，畫面上可能叫 API Keys、Project API、Publishable key…只要是「一串拿來當通行證的字」就對了。找不到一模一樣的字不用慌，找意思最接近的。

② 看到「複製／抄下某個值」，就貼到你的「鑰匙收集表」。不是複製了就好——要先貼到一個記事本存起來，最後步驟 6 會一次把它們全部貼進網站平台。下面步驟 0 有一張現成的表格，先複製到你的記事本。

步驟 0

0

開始前，準備這些

約 10 分鐘

  • 一台電腦（Windows 或 Mac 都可以）與網路。
  • 一個常用的電子信箱（用來註冊下面的服務）。
  • 賣方交給你的東西：這個網站的程式碼（通常是一個 GitHub 連結或一個壓縮檔），以及賣方原本填好的一份設定清單（檔名 .env.example 或 .env.local）。
  • 一個自己的網域（域名），例如 myschool.com。強烈建議先買好（GoDaddy、Cloudflare、Gandi 等都可，一年約數百元）。
    為什麼需要：① 網站最後掛在它底下；② 更關鍵——寄信要用它，沒有自家網域，客戶收不到「註冊驗證信」就無法登入（見步驟 4）。網站本身可先用平台送的免費網址，但寄信一定要自家網域。
  • 刷卡收錢會用到公司/商號的營業登記（PayUni 審核要）。個人也可問 PayUni 可否申請。

💡 提早準備、邊等邊做

「買網域」和「送 PayUni 審核」都建議第一天就先弄——網域 DNS 生效、PayUni 審核都要等，早點開始才不會卡在最後。

步驟 2

2

建立資料庫（Supabase）

約 40 分鐘　這步最多字，但每個動作都很簡單

2-0. 先把程式碼下載到你的電腦

後面很多步驟（貼 SQL、之後搬家跑指令）都需要「打得開專案裡的檔案」。所以先把賣方給你的程式碼放到電腦上：

  • 拿到的是壓縮檔（zip）：解壓縮到一個好找的位置（例如桌面），得到一個 bds-web 資料夾。
  • 拿到的是 GitHub 連結：直接在該頁面按 Code → Download ZIP 下載、解壓縮即可（最簡單）。（之後步驟 6 才需要把 repo 轉到你自己的 GitHub 帳號，現在不用管。）

💡 記住這個資料夾位置

之後手冊只要說「db/ 資料夾的某檔」或「跑 node scripts/... 指令」，都是指這個 bds-web 資料夾裡的東西。

2-1. 建立專案

  1. 登入 Supabase → 按 New project（新專案）。
  2. 取一個名字、選最近的區域（例如 Singapore）。
  3. 它會要你設一組資料庫密碼。請把這組密碼抄下來存好（之後備份會用到）。
  4. 按建立，等它跑好（約 1～2 分鐘）。

2-2. 建立資料表（把「空櫃子」擺好）

✅ 最省事：一行指令全自動（建議給工程師）

在 bds-web 資料夾設好 SUPABASE_DB_URL（這條連線字串怎麼拿：見下方 2-3，選「Session pooler」那條；備份章節 9B 也會用到）後執行：

npm run setup -- --migrate

它會自動把 db/ 內所有必要的 SQL 依正確順序跑完（含日後新增的），你不必自己記有哪些檔。跑完就跳到 2-3。
不會用終端機？跳過這框、直接看下面的「手動做」三步驟即可。

手動做（不用指令）也可以——不必背檔名，只要記住這 3 條規則。左側點 SQL Editor → New query，把檔案整份貼進去、按 Run：

  1. 先跑 db/init.sql（建立所有基礎資料表＋範例資料）。
  2. 再把 db/ 資料夾裡「其餘每一個 .sql 檔」都各跑一次（只跳過 schema.sql 這個參考檔）。這些檔彼此先後順序沒差、也都可以重複跑（跑到重複的會顯示無害訊息，不用理）。
  3. 最後才跑 db/enable_rls.sql（這是「對外上鎖」，一定要放最後；若有 fix_token_rls.sql 也一起放最後跑）。

怎麼打開檔案？在 bds-web/db 資料夾找到該檔，用記事本開 → 全選(Ctrl+A) → 複製(Ctrl+C) → 貼到 SQL Editor。

⚠️ 只要記住：init.sql 先、enable_rls.sql 最後

中間其他檔全部都要跑、順序不拘。這樣日後新增任何資料表/欄位（多一個 .sql 檔），你照這規則做就不會漏，不必更新這份手冊。

2-3. 拿 3 把鑰匙（等一下要貼到上線平台）

點 Supabase 畫面最上方的 Connect 按鈕（把所有金鑰放在同一個視窗，最好找）。抄下這 3 個：

① 專案網址Connect 視窗 → App Frameworks
NEXT_PUBLIC_SUPABASE_URL
② 公開金鑰（給瀏覽器用，新版叫 Publishable key）同上視窗
NEXT_PUBLIC_SUPABASE_ANON_KEY
③ 機密金鑰 ⚠️ 絕不外洩（新版 Secret key / 舊版 service_role）Connect → Secret / Legacy API Keys
SUPABASE_SERVICE_ROLE_KEY

（順手也複製一份「連線字串 Connection string / URI」，把裡面的 [YOUR-PASSWORD] 換成 2-1 設的密碼——步驟 9 備份會用到。現在用不到可先跳過。）

2-4. 建立圖片儲存空間

  1. 左側點 Storage → New bucket。
  2. 名字打 uploads，勾選 Public，建立。

✅ 完成後你會有

一個裝好所有資料表的資料庫、3 把鑰匙抄在手邊、一個 uploads 圖片空間。

步驟 3

3

設定影片（Bunny.net）

約 20 分鐘　沒有課程影片的話可先跳過，之後再補

  1. Bunny → Stream → 建一個 Video Library（影片庫）。
  2. 進這個影片庫的 Security 分頁，打開 Embed View Token Authentication（這就是「防盜開關」，一定要打開防盜才會生效）。
  3. 抄下這 3 個值：
① 影片庫 ID（一串數字）影片庫 → API 分頁
BUNNY_STREAM_LIBRARY_ID
② 防盜金鑰 ⚠️ 機密（播放防盜用）影片庫 → Security 分頁
BUNNY_TOKEN_AUTH_KEY
③ 上傳用 API 金鑰 ⚠️ 機密（批次上傳影片才需要）影片庫 → API 分頁的 AccessKey
BUNNY_STREAM_API_KEY

💡 ② 和 ③ 是不同的兩把鑰匙

② 在 Security 分頁（給播放防盜用）；③ 在 API 分頁（給《搬家手冊》批次上傳影片用）。名字很像，別搞混或以為填過了。

之後在後台新增課程章節時，「影片網址」欄位貼該影片的網址或編號，系統會自動加防盜。

步驟 4

4

設定寄信（Resend）

約 15 分鐘

📖 先分清楚「網域」和「網站上線」是兩回事

這裡說的「你的網域」＝你買下來的那個域名（例如 myschool.com），跟網站有沒有上線完全無關。你一買下網域，它就存在、就能拿去 Resend 驗證了，不需要等網站架好。

舉例：假設你買的網域是 myschool.com，那寄件人就填 no-reply@myschool.com（no-reply 是自訂的、不用另外去申請這個信箱，Resend 驗證過網域後就能用）。

👉 還沒有自己的網域嗎？要收費賣課，建議先去買一個（GoDaddy、Cloudflare、Gandi 等都可）。買好之前，先照下面的「還在等驗證時怎麼先測」用沙盒地址測試即可，但別對外開放收客。

  1. Resend → 左側 API Keys → Create，複製那把鑰匙。
  2. 左側 Domains → Add Domain → 輸入你買的網域（例如 myschool.com）→ 依畫面指示到你買網域的地方加上它給的 DNS 記錄 → 等變成 Verified。之後寄件人就設成 no-reply@你的網域。對外收客前必做

⚠️ 這步不能跳過，否則新客戶會「註冊了卻無法登入」

新客戶註冊後，系統會寄一封「驗證信」，客戶要點了才能登入。若寄件人還用預設的沙盒地址 onboarding@resend.dev，Resend 只會把信寄到你自己、真正的客戶永遠收不到驗證信 → 就登不進去、買了也用不了。購買通知信、忘記密碼信也一樣收不到。

所以：正式對外收客前，一定要驗證自家網域、把寄件人換成 no-reply@你的網域（例如 no-reply@myschool.com）。

寄信鑰匙Resend → API Keys
RESEND_API_KEY
寄件人信箱（驗證網域後填；例如網域是 myschool.com 就填 no-reply@myschool.com）
RESEND_FROM_EMAIL = no-reply@你的網域
測試收件信箱（網域還沒驗證好、想先測試時填你自己的信箱）用沙盒寄件人時，信只會寄到這裡
RESEND_TEST_RECIPIENT = 你自己的信箱@example.com
聯絡表單的收件信箱（填你自己的客服信箱）
CONTACT_TO_EMAIL = 你的客服信箱@example.com

💡 還在等網域驗證時怎麼先測？

可暫時 RESEND_FROM_EMAIL = onboarding@resend.dev 並填上面的 RESEND_TEST_RECIPIENT，此時所有信只會寄到你自己的信箱（方便看信長怎樣）。但這只是測試用，對外收客前務必換成自家網域。

步驟 5

5

設定刷卡（PayUni）

審核通過後約 10 分鐘 要等審核

等步驟 1 送的商家審核通過後，回來做這步。

  1. 登入 PayUni 後台 → 會員 → 商店清單 → 點 SHOP 開頭的商店 → 串接設定 → 《API 串接金鑰》。
  2. 抄下 3 個值（測試階段先用 Sandbox 測試那組）。
商店代號、加密金鑰、加密向量PayUni → API 串接金鑰
PAYUNI_MERID       = 你的商店代號
PAYUNI_HASH_KEY    = 你的 HashKey
PAYUNI_HASH_IV     = 你的 HashIV
付款頁網址（測試先用 sandbox，正式上線再換）
# 測試階段：
NEXT_PUBLIC_PAYUNI_UPP_URL = https://sandbox-api.payuni.com.tw/api/upp
# 正式收真錢時改成：
# NEXT_PUBLIC_PAYUNI_UPP_URL = https://api.payuni.com.tw/api/upp
NEXT_PUBLIC_PAYUNI_MERID   = 你的商店代號（同上）

💡 不用手動填回呼網址

系統送出付款時會自動帶上回呼網址。若 PayUni 後台有 Notify URL 欄位要你填，就填 https://你的網站網址/api/webhook/payuni（這裡指「網站上線後的網址」，步驟 6 部署完才會有；跟上面 Resend 的「網域」是不同東西）。

步驟 6

6

把網站放上線（Netlify 或 Cloudflare，二選一）

約 30 分鐘　這步做完就有一個能開的網址了

🅰️🅱️ 先選一個放網站的平台（本系統兩個都支援）

  • 路線 A：Netlify——設定最簡單、最直覺。適合新手。免費額度（尤其每月建置次數）較小，網站更新很頻繁時可能會不夠用。
  • 路線 B：Cloudflare——免費額度大很多（建置次數、流量），且允許商業使用；但設定稍微技術一點，建議請工程師協助。

兩條路的「環境變數（鑰匙）」完全一樣，差別只在「在哪裡匯入 repo、按哪個部署」。先做 6-1（共用），再挑 A 或 B。

6-1. 讓程式碼進到你的 GitHub（A、B 共用）

6-B. 路線 B：改用 Cloudflare（免費額度更大，稍技術，建議工程師）

👷 這條路偏技術，建議由工程師執行；採「連 GitHub 自動部署」

本專案已內建 Cloudflare 設定檔（wrangler.jsonc 已含 nodejs_compat 旗標，你不用自己加）。我們統一用「連 GitHub」的方式——這樣以後每次工程師 push 更新，Cloudflare 都會自動重新部署，不用每次手動上傳。

💳 免費版塞不下：要先開 Workers Paid（約 US$5／月）

Cloudflare Workers 免費版「單一程式上限 3 MiB」，本站（完整 Next.js）會超過、部署會失敗（exceeded the size limit of 3 MiB）。請先開 Workers Paid（約 US$5／月，上限 10 MiB） 再部署。（仍比 Netlify 付費便宜、額度大方。）

步驟（做完 6-1 後）：

  1. Cloudflare → Workers & Pages → Create → Import a repository，選你的 bds-web 倉庫。
  2. 建置指令填 npx opennextjs-cloudflare build、部署指令填 npx wrangler deploy。
  3. 在該專案 → Settings 的變數設定，依下表新增環境變數（值＝你在 6-3「鑰匙收集表」填過的那些）。類型很重要：
設「一般（Plaintext）」— build 期要讀，一定不能設成 Secret設「Secret（加密）」— 伺服器機密
NEXT_PUBLIC_SUPABASE_URL、NEXT_PUBLIC_SUPABASE_ANON_KEY、NEXT_PUBLIC_PAYUNI_UPP_URL（正式端點）、NEXT_PUBLIC_PAYUNI_MERID、NEXTAUTH_URL、PAYUNI_MERID、RESEND_FROM_EMAIL、BUNNY_STREAM_LIBRARY_ID、ENABLE_PAYMENT_SIMULATION(=false)、NODE_VERSION=22、（選填）CONTACT_TO_EMAIL／ADMIN_ALERT_EMAIL SUPABASE_SERVICE_ROLE_KEY、NEXTAUTH_SECRET、PAYUNI_HASH_KEY、PAYUNI_HASH_IV、RESEND_API_KEY、BUNNY_TOKEN_AUTH_KEY、BUNNY_STREAM_API_KEY

🧨 為什麼 NEXT_PUBLIC_ 一定要設「一般」

這些值是在建置（build）當下就寫死進前端的。若設成 Secret，build 期讀不到 → 前端會用預設沙盒值 → 刷卡看起來正常、卻打到測試端點、收不到真錢。所以 NEXT_PUBLIC_PAYUNI_UPP_URL 務必填「正式端點」且設「一般」。

⚡ 想更快？右邊「Secret」那一整欄，可用一行指令整包匯入

你電腦上的 .env.local 已經把所有鑰匙填好了。右邊「Secret（機密）」那一欄不用一個一個貼，可以用工具一次全部上傳（左邊「一般」那欄仍要手動貼，因為它們 build 期才用得到，這個指令不管 build）。

做法（要先完成上面第 1～3 步、按過第一次部署，讓 Worker bds-web 先存在）：在專案資料夾打開終端機，執行這兩行：

一次匯入所有機密（讀你填好的 .env.local）電腦 → 專案資料夾終端機
npx wrangler login
npx wrangler secret bulk .env.local

說明：wrangler secret bulk 會讀 KEY=VALUE 格式，一次最多 100 個。它會把 .env.local 整包當機密上傳（那 4 個 NEXT_PUBLIC_ 也會一起上去、無害）——但它們仍必須另外在上面「一般」欄設定，build 才讀得到。上傳完到 Deployments 重新部署一次即生效。

  1. NEXTAUTH_URL 第一次先隨意填（例如暫填 https://example.com）→ 部署 → 取得 Cloudflare 給的 *.workers.dev 測試網址 → 回來把 NEXTAUTH_URL 改成它 → 到 Deployments 觸發一次重建。
  2. 用該測試網址把功能點一遍：登入、看片、真卡買一筆（確認金流走正式端點、收得到錢）、後台。
  3. （之後有自己網域）該專案 → Settings → Domains & Routes 綁你的網域；把 NEXTAUTH_URL 改成正式網域，再到 Deployments 觸發重建。
  4. 日後工程師 push 到 GitHub 會自動重建部署；只改環境變數（尤其 NEXT_PUBLIC_）時，要到 Deployments 手動觸發一次重建才生效。

⚠️ 兩個平台擇一就好

同一個網域只能指向一個平台。先用測試網址確認新平台一切正常（尤其真卡刷一筆），再把網域切過去，然後才停用另一個。切換網域屬技術操作，建議工程師處理。

一個可以打開的網站！先點進去看看首頁、課程頁有沒有正常顯示。

8

開門收客前的安全檢查

約 20 分鐘　開始收真錢之前，這幾項一定要確認

⚡ 先跑「一鍵驗收」，讓電腦幫你檢查一遍

在專案 bds-web 資料夾（需先照《搬家手冊》附錄裝好 Node＋npm install）執行：

npm run verify

※ 若你全程都在網頁上設定、電腦裡從沒建過 .env.local，這支會滿螢幕紅字（因為它讀本機的 .env.local）。請先照《搬家手冊》附錄②把 .env.example 複製成 .env.local，填好 Supabase 兩把金鑰、NEXTAUTH_URL、NEXTAUTH_SECRET，再跑本檢查。這支是「給會用電腦指令的人」的加分檢查；不跑也能上線，但強烈建議請工程師幫你跑一次。

它會自動體檢：環境變數、資料庫 17 張表、限流函式、圖片空間、管理員帳號、線上網站是否活著——全程唯讀、不會改任何東西。看到「全部必要項目通過！」就代表地基沒問題；有紅色 ✗ 會直接告訴你缺什麼、怎麼補。下面的清單則是這支工具檢查不到、需要你「親手實測」的部分。

  • 資料保護鎖有打開（資安最重要）：上面的 npm run verify 會自動檢查這項（「資料庫對外上鎖」）。若顯示未上鎖，代表步驟 2 最後的 db/enable_rls.sql 沒跑到——回步驟 2 把它整份再貼一次即可。
  • 安全開關關好：部署平台（Netlify／Cloudflare）的環境變數裡 ENABLE_PAYMENT_SIMULATION 必須是 false（不然有人能免費開通會員）。
  • 金流換正式：確認商家審核通過後，把 NEXT_PUBLIC_PAYUNI_UPP_URL 換成正式端點、金鑰換成正式那組，重新部署。
  • 網址填對：NEXTAUTH_URL 已改成你真正的網址（不是預設的假網址）。
  • 寄信正常（很重要）：RESEND_FROM_EMAIL 已改成自家已驗證網域（不是 onboarding@resend.dev）。實測：用另一個信箱到 /signup 註冊 → 該信箱能收到「驗證信」→ 點了能成功登入。收不到＝客戶也會收不到、無法登入。
  • 真卡實測：用一張真卡買一筆最便宜的商品，確認「付款成功 → 自動開通 → 收到通知信」整條走得通，再退刷。（系統設計上同一筆只會開通一次，不會重複扣款。）
  • 付費內容保護：之後上傳的付費影片/下載檔/教材會自動放進「私有空間」、只發會過期的短連結。若先前上傳過測試的付費檔，請重新上傳一次，舊的才會受保護。
  • 換成你的品牌：後台「設定」把站名、Logo、主色、聯絡信箱、FAQ、公告改成你自己的；刪掉範例課程與範例訂單。
  • 備份與保活已生效（在步驟 9 設定）：先做完下面的步驟 9（保活、每日備份），再回來確認它們都測試成功、打勾。（沒設好的話：網站閒置會睡著、資料也沒有備份。）

✅ 這一頁就是你的完整清單

上面這幾項就是上線前要確認的全部。（npm run verify 是「進階選配」，需先照《搬家手冊》附錄裝好環境；不會用也沒關係、不跑也能上線。）逐項打勾都通過，就可以安心開門收客了。

步驟 9

📍 這一步是在「GitHub」做，不是 Netlify

下面的保活、備份、通知、自動續命，都是 GitHub 幫你在背景自動跑的工作，跟「放網站的平台」（Netlify 或 Cloudflare）是不同的地方。所以這一步請打開你的 GitHub。

9-0

先開啟並確認 GitHub Actions（做一次）

約 3 分鐘　所有背景自動工作都靠它，先確認它是開的

  1. 打開你的專案頁：瀏覽器登入 github.com → 點進你的專案（例如 你的帳號/bds-web）。
  2. 點最上方一排分頁裡的 Actions（在 Code、Issues、Pull requests… 那一排）。
  3. 看到什麼？兩種情況：
    • A. 出現一個綠色按鈕寫「I understand my workflows, go ahead and enable them」 → 按它一下。這代表 Actions 剛被啟用。（這就是「生效」的動作。）
    • B. 直接看到左側一排工作名稱（Supabase 保活、每日資料庫備份、網站健康檢查、自動保持 repo 活躍…）→ 代表已經是開的，不用再按。

只要在 Actions 分頁能看到工作清單、且手動跑一次是綠勾，就代表 GitHub 會照排程自動幫你做。接著再做 9A～9C 把各自要的值填上。

9A

開啟「保活」—— 這步請務必做

約 5 分鐘　很簡單，只是貼 2 個值

⚠️ 為什麼一定要做

免費版的資料庫約 7 天沒人使用就會「睡著」，睡著時客戶會遇到網站打不開或很慢。系統已內建一個「每 3 天自動戳一下」保持清醒的功能，但要你貼 2 個值它才會啟動。這步做完就一勞永逸、全自動。

💡 這 2 個值就是步驟 2 抄過的那組

就是步驟 2 的 NEXT_PUBLIC_SUPABASE_URL（專案網址）和公開金鑰，值一模一樣；只是 GitHub 這裡的欄位名不帶 NEXT_PUBLIC_ 前綴（叫 SUPABASE_URL／SUPABASE_ANON_KEY），不是另一把新鑰匙，別緊張。

  1. 到你的 GitHub 專案頁 → 上方 Settings（齒輪）→ 左側 Secrets and variables → Actions。
  2. 按綠色 New repository secret，新增第一個：
    Name 填這個
    SUPABASE_URL
    Value 貼你的專案網址（步驟 2 抄的那個）
    https://xxxx.supabase.co
  3. 再按一次 New repository secret，新增第二個：
    Name 填這個
    SUPABASE_ANON_KEY
    Value 貼你的公開金鑰（Publishable key，步驟 2 抄的）
    eyJ....（一長串）
  4. 到專案上方 Actions 分頁 → 左側點 「Supabase 保活（防免費版休眠）」 → 右側 Run workflow 跑一次測試。看到綠色打勾、日誌顯示 回應碼：200 就成功了。之後每 3 天自動跑，不用再管。

✅ 完成後

你的資料庫不會再因為沒人來而睡著，客戶隨時打開都順暢。

🗓️ 這個系統已幫你自動處理（了解即可）

※ 注意：這是「排程保活（每 10 天）」，和步驟 9A 的「資料庫保活（每 3 天）」是兩件不同的事——前者防 GitHub 停用排程、後者防 Supabase 資料庫睡著。兩個都已自動，你不用記。

GitHub 有個規則：專案連續約 60 天沒有任何變更，會自動把排程（保活/備份/健康檢查）停用。本系統已內建「排程保活」，每 10 天自動更動一次讓專案保持活躍，所以正常情況你不用手動處理。
備援起見，若哪天想確認，可到 GitHub → Actions 看一眼；萬一看到 workflow 被停用（有 Enable workflow 按鈕），按一下重新啟用即可。

9B

每日備份到 Google Drive（選配，進階）

約 30 分鐘 可晚點做／找人幫一次

設定每天自動備份你的資料庫。備份有兩層：一層存成 GitHub 的檔案（保留 90 天），一層另外存到你的 Google Drive。

⚠️ 備份不是「零設定就有」——要先貼 1 個值它才會跑

備份需要能連到資料庫的「連線字串」。請比照 9A，到 GitHub → Settings → Secrets and variables → Actions 再新增一個 secret：

Name 填這個
SUPABASE_DB_URL
Value 貼資料庫連線字串（把 [YOUR-PASSWORD] 換成步驟 2-1 的密碼）Supabase → Connect → Connection string → 選「Session pooler」
postgresql://postgres.xxxx:你的密碼@aws-0-<region>.pooler.supabase.com:5432/postgres

⚠️ 一定要選「Session pooler」那條（網址是 ...pooler.supabase.com）。不要用「Direct connection」（db.xxxx.supabase.co）——它只支援 IPv6，GitHub 的備份機器連不到，備份會失敗。

設好後，到 Actions 分頁點 「每日資料庫備份」 → Run workflow 跑一次，看到綠色打勾、且在該次紀錄下方 Artifacts 出現 db-backup 檔，才代表備份真的有生效。沒設這個值的話，備份會失敗、你其實一份都沒有。

💡 Google Drive 那層可以晚點做（進階）

把備份「另存一份到 Google Drive」比較技術（要設 rclone），建議找懂電腦的人幫你設定一次，專案裡的 SETUP-GUIDE.md 步驟 8 有完整指令。只要上面的 SUPABASE_DB_URL 設好了，GitHub 檔案那層備份就已經在保護你了，Google Drive 是再加一層。

9C

開啟「出錯自動通知」（建議做，5 分鐘）

系統半夜壞了主動通知你，不用等客戶客訴

兩層通知，都免費、免額外帳號：

① 網站當機通知（用 GitHub）

系統每小時自動戳一次你的網站，若打不開（當機／資料庫睡著／部署壞掉），GitHub 會自動寄信通知你。只要再加 1 個 secret：

GitHub → Settings → Secrets and variables → Actions，Name 填這個
SITE_URL
Value 貼「你的新網站『現在』實際打得開的網址」
https://你的新網站網址

⚠️ 還沒換網域前，填平台的臨時網址（搬家的人尤其注意）

填「新網站現在真的打得開」的網址：還沒換網域前，就是部署平台給的臨時網址（Netlify 的 xxxx.netlify.app 或 Cloudflare 的 xxxx.workers.dev）。等正式換好網域後，再回來把它改成你的網域（例 https://myschool.com）。

搬家情境特別注意：換網域完成前，千萬別填你舊站現在的網域（那個還指向舊 Teachify、還在營運的網址）——填了等於在監控舊站、而不是你的新站。要等《搬家手冊》換網域、新站穩定後才改成正式網域。

（確認 GitHub 帳號的 Email 通知有開：GitHub 預設會在排程工作「失敗」時寄信給你，等於網站掛掉就收到通知。）

② 金流開通失敗通知（用 Resend）

最怕的狀況是「客戶付了錢，但系統沒開通」。發生時系統會主動寄一封警示信給你去手動補開通。在部署平台（Netlify／Cloudflare）的環境變數加一個信箱即可（不加則退回用你的客服信箱）：

部署平台環境變數（Netlify／Cloudflare）
ADMIN_ALERT_EMAIL = 你要收警示信的信箱

💡 想要更專業的錯誤追蹤（選配）

若之後想升級成「每一個程式錯誤都記錄＋分析」，可接免費的 Sentry（有免費額度）；或用 UptimeRobot 免費版做更密集（每 5 分鐘）的當機監控。這兩個要另外註冊帳號，屬進階加值，不做也不影響上面兩層基本通知。

長期維護

網站顧好，其實只有幾件事

這套系統跑在幾個「免費方案 + 第三方服務」上，所以不是「裝完永遠不用理」，但要顧的東西很少。把下面看一遍，設幾個提醒就好。

🗓️ 定期要做的（設進手機行事曆最保險）

  • 排程維持啟用：系統已內建「自動保活」每 10 天更動一次，正常不用管；偶爾想確認可到 GitHub → Actions 看一眼，若有被停用就按 Enable workflow。
  • 每年：網域續約（在你買網域的地方）。忘了續，網站會整個消失——這是最常見的意外，建議開自動續約。
  • 偶爾：確認每日備份有在跑（GitHub → Actions →「每日資料庫備份」→ 最近一次有綠勾、Artifacts 有檔）。

🔁 改設定的重要小知識：程式會自動部署，改「環境變數」不會

改程式碼（工程師 push 到 GitHub）→ 部署平台（Netlify／Cloudflare）會自動重新編譯、自動上線，不用手動按。

但只改「環境變數」（例如改 NEXTAUTH_URL、換金流正式金鑰、換寄件網域）→ 不會自動生效，要「重新部署」一次新值才會套用：Netlify 到 Deploys → Trigger deploy（選 Clear cache and deploy site）；Cloudflare 到該 Worker 的 Deployments 觸發一次重建。特別是 NEXT_PUBLIC_ 開頭的值（如金流正式端點）改了一定要重新部署，否則前端還是舊值。這是最常被忽略、卻常讓人以為「改了怎麼沒用」的點。

🔔 系統會主動通知你嗎？（誠實說）

部分會、部分要自己留意。

  • ✅ 網站掛掉：若你設了步驟 9C 的健康檢查，掛掉時 GitHub 會寄信給你。
  • ✅ 付款成功卻沒開通：系統會主動寄警示信（步驟 9C）。
  • ⚠️ 免費額度快用完：我們系統不會通知，但各家服務商通常會自己寄 email 提醒你，也會出現下面說的「症狀」。所以請把註冊這些服務的信箱顧好、別漏看它們的信。

免費額度用完會怎樣？何時要升級付費？

服務免費大概到哪、用完的「症狀」怎麼看用量 / 何時升級
Resend 寄信免費約每月 3,000 封、每天 100 封。用完時信寄不出去——新客戶收不到驗證信＝無法登入（很有感）。Resend 後台看用量；學員多、寄信量大時升級付費方案。
Supabase 資料庫免費約 500MB 資料、儲存與流量有限；超過時讀寫會變慢或被擋。Supabase 後台 → Usage 看用量；學員/資料成長到接近上限就升級。
放網站平台（Netlify／Cloudflare）免費有流量/建置額度；爆量時可能被限流或無法重新建置。各自後台看用量：Netlify 用量頁；Cloudflare 在該 Worker 的 Metrics。額度不夠再升級或改用另一平台。
Bunny 影片這個本來就不是免費的——按影片儲存與觀看流量計費（費用通常不高，但要綁定付款方式，會實際扣款）。Bunny 後台看帳單；隨觀看量成長費用會增加，屬正常營運成本。

（實際數字以各家官網公告為準，方案偶爾會變。重點是：學員/流量成長 = 早晚要把幾個服務升級成付費，這是生意做起來的正常成本，不是壞掉。）
