從 Teachify 搬到你自己的系統

把課程、學員、影片搬過來，客戶無縫接軌

這份教你把原本 Teachify 上的一切搬到新網站，並讓你的 656 位學員繼續看到他們買過的課。

👋 先懂大方向（1 分鐘）

搬家分「內容」和「人」兩部分。內容（課程、影片、文章）要重新放進新系統；人（656 位學員＋他們買過哪些課）我們已經做好自動匯入工具，不用一個個手打。

最後把網址 bds.fu-notes.com 從 Teachify 改指到新網站，客戶用同一個網址就繼續用了。

⏳ 有一件事客戶一定要做一次：重設密碼

密碼沒有任何平台能匯出（Teachify 也不行），所以搬不過來。做法是：我們幫每位學員自動寄一封「設定新密碼」信，他點一下設定好，就能用原本的 Email 繼續登入看課。這是唯一要客戶動手的一次，其他都無感。

搬家順序

照這 6 步做

🖥️ 開始前：跑任何指令前，先完成這 4 件事

本手冊步驟 2～5 都要在電腦的終端機打 node ... 指令。第一次做之前，請先備妥（文末附錄「用之前先確認」有更詳細步驟）：

  1. 把專案下載到你的電腦：git clone 你的 GitHub 專案（或解壓賣方給的檔），得到一個 bds-web 資料夾——後面所有指令都在這個資料夾裡跑。
  2. 裝 Node.js（nodejs.org 下載 LTS 版），並在 bds-web 資料夾執行一次 npm install。
  3. 建立 .env.local：把 .env.example 複製改名為 .env.local，填入你自己新專案的金鑰（見附錄，含 Bunny 上傳金鑰 BUNNY_STREAM_API_KEY）。切勿沿用賣方舊檔，否則會灌到賣方的舊資料庫。
  4. 從 Teachify 匯出學員 CSV：到 Teachify 後台匯出學員名單（需含 Email 與 Attended courses 欄位），存到電腦，記下路徑（下面指令的「你的CSV路徑」就是它）。
1

先把新網站架好

照《BDS 開站手冊》把新系統上線（Supabase、Netlify 等都設定好）

還沒架好的話，先看同一個 docs 資料夾裡的 buyer-setup-guide.html。那份做完，你會有一個能登入後台 /admin 的空網站，接著才開始搬東西。

2

把影片批次上傳到 Bunny（自動工具）

你手上有原始影片檔，這步就沒問題

（步驟 2 上傳影片與步驟 3 建立課程，先後順序沒差、互不影響；等兩者都好了，再把影片網址貼進課程章節即可。文末速查表為方便起見先列建課。）

把影片檔放進一個資料夾（建議：一個子資料夾一門課、檔名就是章節名，這樣對應最準）。然後先掃描看看（不會上傳、不用金鑰）：

node scripts/bunny-upload.mjs "你的影片資料夾"

它會產生一份 bunny-upload-plan.csv，列出找到幾支、以及「猜的課程/章節」。看一下對不對，然後正式上傳（可先加 --limit 3 傳 3 支測試）：

node scripts/bunny-upload.mjs "你的影片資料夾" --upload

上傳完會給你 bunny-upload-result.csv——每支影片對應的 Bunny 網址，之後步驟 3 貼進章節時照這張表即可。

⏳ 兩個提醒

① 影片檔很大、上傳要時間，工具可以中斷後續傳（重跑會自動略過已傳的），不怕斷線。
② 需要 Bunny 影片庫的「上傳用 API Key」（BUNNY_STREAM_API_KEY，在 Bunny → Stream → 影片庫 → API），它跟播放防盜的金鑰是不同的東西。

3

自動建立課程空殼（標題保證一致）

這是讓學員權限對得上的關鍵，改用工具就不會打錯字

學員權限是「用課程標題對應」的，所以標題必須跟 Teachify 完全一致。與其手動建 26 門、還怕打錯，直接用工具照 CSV 自動建好空殼：

先試跑看會建哪些（不寫入）：

node scripts/create-course-shells.mjs "你的CSV路徑"

沒問題後正式建立：

node scripts/create-course-shells.mjs "你的CSV路徑" --commit

它會依 CSV 算出的門數自動建好空殼（本例約 26 門，實際以工具印出的數字為準；標題完全正確、狀態為「未發佈」）。接著你到後台 /admin 為每門課補上說明、把步驟 2 上傳的影片網址貼進章節（貼 bunny-upload-result.csv 裡的 embed_url 或 bunny_guid 皆可，系統都認得），完成後記得按「發佈」課程才會對外顯示。

4

匯入學員與課程權限（自動）

656 位學員一次匯入，不用手打

第一步：只看 CSV（最安全，不連資料庫）。先確認人數與課程清單讀得對：

node scripts/import-students.mjs "你的CSV路徑" --preview

第二步：試跑（會連你的資料庫比對課程標題、但不寫入；此步需 .env.local 已設好）：

node scripts/import-students.mjs "你的CSV路徑"

它會告訴你課程標題「有幾種對上了、哪幾種還沒對上（打錯字或還沒建）」。全部對上後，正式匯入：

node scripts/import-students.mjs "你的CSV路徑" --commit

✅ 完成後

656 位學員都建好了，每個人也自動開通了他在 Teachify 買過的課。可以重複跑，不會重複建立。

5

寄「設定新密碼」信給全體學員（自動）

客戶點一下就能繼續用

⏳ 寄信前兩個前提（都要滿足才 --send）

① 寄件人網域：RESEND_FROM_EMAIL 必須是已驗證的自家網域（例如 no-reply@你的網址）。還在用沙盒地址的話工具會擋下。要先驗證網域
② 網址要先定案：信裡的「設定密碼」連結是用 .env.local 的 NEXTAUTH_URL 組出來的、效期 7 天。所以請先把 NEXTAUTH_URL 設成客戶最終會用的正式網址（https://bds.fu-notes.com）再 --send；否則連結會指到臨時網址，切換網域後可能失效。最穩的做法：把這步（--send）放到步驟 6 換好網域、確認新站能登入之後再做。

先寄一封測試信給自己看版面（測試信只是預覽版型，裡面的連結點了不會真的能設密碼，正式 --send 才會產生有效連結）：

node scripts/send-invites.mjs "你的CSV路徑" --test 你的信箱@example.com

兩個前提都滿足後，正式寄給全部人（每封間隔 0.4 秒，自動避開寄信限制）：

node scripts/send-invites.mjs "你的CSV路徑" --send

學員收到信 → 點按鈕 → 設定新密碼 → 用原本 Email 登入，課程權限都在。

6

把網址切到新網站

客戶用同一個網址無縫接軌

  1. 先在新網站的臨時網址上把 1～5 步全部測好（登入、看課、金流都正常）。
  2. 確認無誤後，到你的網域管理處（買 fu-notes.com 的地方），把 bds.fu-notes.com 的指向從 Teachify 改到 Netlify（Netlify 的 Domain 設定會給你要填的值）。
  3. 同時把新網站的 NEXTAUTH_URL 改成 https://bds.fu-notes.com，重新部署。
  4. 切換後有幾分鐘～幾小時的生效時間，建議選離峰時段做。

✅ 完成！

客戶打開 bds.fu-notes.com（同一個網址），就進到你的新系統了。之後不用再付 Teachify 年費。

一眼看懂

哪些無縫、哪些要動手

項目狀況
網址✅ 不變（同一個 bds.fu-notes.com）
學員名單、電話✅ 自動匯入
已購課權限✅ 自動保留（依課程標題對應）
登入密碼⚠️ 客戶要重設一次（自動寄信邀請）
影片⚠️ 用原始檔重新上傳 Bunny
課程／文章文字⚠️ 手動重建（標題要一致）

🆘 步驟 2～5 都是電腦指令，不會用怎麼辦？

步驟 2～5 都要在電腦終端機執行 node ... 指令。可以請一位懂電腦的人幫你跑一次（約 1 小時，含上傳影片），把這份說明直接給他看即可。跑完之後，日常經營（上架課程、看訂單）你自己在後台就能全掌握。

附錄

指令速查表（搬家當天照順序複製貼上）

📌 用之前先確認（第一次跑一定要看）

① 裝好 Node.js 並安裝套件。先到 nodejs.org 下載安裝 Node.js（選 LTS 版）。然後開終端機、切到 bds-web 資料夾，執行一次：

npm install

（這會安裝腳本用到的套件。沒做的話，一跑就會噴 Cannot find module 而失敗。）

② 在 bds-web 資料夾建立 .env.local，填「你自己」的鑰匙。把專案裡的 .env.example 複製一份、改名為 .env.local，填入你自己新建的 Supabase 專案金鑰（NEXT_PUBLIC_SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY），以及 NEXTAUTH_URL、Resend（RESEND_API_KEY、RESEND_FROM_EMAIL）、Bunny 的鑰匙。

⚠️ 千萬別直接沿用賣方交給你的舊 .env.local

裡面是賣方的舊鑰匙，會連到賣方的舊資料庫，把課程和 656 位學員灌錯地方。一定要換成你自己新專案的鑰匙。

③ 影片上傳要多一把鑰匙。步驟 2 的 bunny-upload.mjs 需要 BUNNY_STREAM_API_KEY（Bunny → Stream → 影片庫 → API 分頁，和播放防盜金鑰不同），記得也填進 .env.local。

④ 路徑替換：把指令裡的 你的CSV路徑 換成實際位置，例如 "../BDS-students-2026-08-24.csv"。

▸

依序執行

每一步都「先試跑、再正式做」，確認數字對了才加 --commit / --upload / --send

① 建立 26 門課空殼（標題保證正確）

node scripts/create-course-shells.mjs "你的CSV路徑"            # 先試跑看清單
node scripts/create-course-shells.mjs "你的CSV路徑" --commit   # 正式建立

② 影片批次上傳 Bunny（→ 產生對照表）

node scripts/bunny-upload.mjs "你的影片資料夾"                 # 先掃描看 plan.csv
node scripts/bunny-upload.mjs "你的影片資料夾" --upload --limit 3   # 先傳 3 支測試
node scripts/bunny-upload.mjs "你的影片資料夾" --upload        # 全部上傳（可中斷續傳）

→ 依 bunny-upload-result.csv 到後台把影片網址貼進各課章節，補完內容後發佈課程。

③ 匯入 656 位學員 + 課程權限

node scripts/import-students.mjs "你的CSV路徑"                 # 試跑：看課程標題對不對得上
node scripts/import-students.mjs "你的CSV路徑" --commit        # 正式匯入

④ 寄「設定新密碼」信給全體學員

node scripts/send-invites.mjs "你的CSV路徑" --test 你的信箱     # 先寄一封測試給自己
node scripts/send-invites.mjs "你的CSV路徑" --send             # 正式寄給全部人

→ 寄全體前，RESEND_FROM_EMAIL 必須是已驗證的自家網域，否則工具會擋下。

⑤ 最後：把網址切到新站（見上方步驟 6）

全部測好後，才把 bds.fu-notes.com 從 Teachify 改指到 Netlify。

✅ 順序邏輯

先有課（①）→ 影片就位（②）→ 灌人和權限（③）→ 通知客戶（④）→ 換網址（⑤）。順序別跳，權限才對得上。
