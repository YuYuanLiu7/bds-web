從 Teachify 搬到你自己的系統

把課程、學員、影片搬過來，客戶無縫接軌

這份教你把原本 Teachify 上的一切搬到新網站，並讓你的 656 位學員繼續看到他們買過的課。

🛠️ 先看這裡：這份是給「執行搬家的人」看的技術指引

搬家步驟 2～4 需要開電腦終端機打指令、安裝 Node、設定金鑰檔，屬於工程師等級的操作，不建議完全沒有技術背景的人自行執行。而且搬家是一次性、會寄信給全部真實客戶的操作，做錯代價高。

👉 正確做法：由賣方或一位懂電腦的人幫你跑一次（在他的電腦上、填入你的新金鑰，依序跑幾支腳本，約 30 分鐘＋影片上傳時間）。把這份說明整份交給他即可。你只要負責提供資料（Teachify 匯出的 CSV、影片原始檔）與最後驗收。

👋 先懂大方向（1 分鐘）

搬家分「內容」和「人」兩部分。內容（課程、影片、文章）要重新放進新系統；人（656 位學員＋他們買過哪些課）我們已經做好自動匯入工具，不用一個個手打。

最後把網址 bds.fu-notes.com 從 Teachify 改指到新網站，客戶用同一個網址就繼續用了。

⏳ 有一件事客戶一定要做一次：重設密碼

密碼沒有任何平台能匯出（Teachify 也不行），所以搬不過來。做法是：我們幫每位學員自動寄一封「設定新密碼」信，他點一下設定好，就能用原本的 Email 繼續登入看課。這是唯一要客戶動手的一次，其他都無感。

⛔ 動工前必過關卡①：你能改 fu-notes.com 的 DNS 嗎？

「同一個網址 bds.fu-notes.com 無縫接軌」這件事，完全取決於你能不能自行把它的 DNS 從 Teachify 改指到 Netlify。開工前先確認：

  • (a) fu-notes.com 登記在你名下、你能登入網域註冊商後台自行改 DNS → 可照本手冊做。
  • (b) 網域是 Teachify 提供/代管、你只能在 Teachify 後台設定 → 你改不了 DNS，第 5 步做不到。要嘛先向 Teachify 取得網域移轉／DNS 委派，要嘛改用一個你自己的新網域並公告客戶新網址。
  • (c) 網域在別人（前員工/代理商）手上 → 先取回控制權。

沒通過這關（不是 a），先別進到步驟 5——否則搬到一半才發現網址切不過去。
註：寄信（Resend）驗證網域也需要同樣的 DNS 控制權（要加驗證用的 DNS 記錄），所以這關也決定信寄不寄得出去。

⛔ 動工前必過關卡②：先把 Teachify 上的東西「拿齊」再說

Teachify 一旦停用/欠費，上面的東西可能被關、永久拿不回。所以搬家前先逐項確認都拿到手（放自己電腦）：

  • 學員名單 CSV（含 Email、Attended courses）
  • 每一門課、每一支影片的原始檔——逐一對照課程數與章節數點名，別漏
  • 每門課的說明、章節文字、文章內容另存備份（這些要手動重建，沒存底就要重打）
  • 歷史訂單／交易／營收紀錄（對帳、退款、報稅用；Teachify 一關就查不到）

這些沒拿齊之前，絕對不要停用或讓 Teachify 欠費。

搬家順序

照這 5 步做

🖥️ 開始前：跑任何指令前，先完成這 4 件事

本手冊步驟 2～4 都要在電腦的終端機打 node ... 指令。第一次做之前，請先備妥（文末附錄「用之前先確認」有更詳細步驟）：

  1. 把專案下載到你的電腦：git clone 你的 GitHub 專案（或解壓賣方給的檔），得到一個 bds-web 資料夾——後面所有指令都在這個資料夾裡跑。
  2. 裝 Node.js（nodejs.org 下載 LTS 版），並在 bds-web 資料夾執行一次 npm install。
  3. 建立 .env.local：把 .env.example 複製改名為 .env.local，填入你自己新專案的金鑰（見附錄，含 Bunny 上傳金鑰 BUNNY_STREAM_API_KEY）。切勿沿用賣方舊檔，否則會灌到賣方的舊資料庫。
  4. 從 Teachify 匯出學員 CSV：到 Teachify 後台匯出學員名單（需含 Email 與 Attended courses 欄位），存到電腦，記下路徑（下面指令的「你的CSV路徑」就是它）。
1

先把新網站架好

照《BDS 開站手冊》把新系統上線（Supabase、Netlify 等都設定好）

還沒架好的話，先看同一個 docs 資料夾裡的 buyer-setup-guide.html。那份做完，你會有一個能登入後台 /admin 的空網站，接著才開始搬東西。

2

把課程內容搬進來

建立課程 → 上傳影片與教材 → 貼進章節 → 發佈

這一步把 Teachify 上的課程整包搬過來。裡面有 4 個小步，照順序做最順。

2-1. 自動建立課程空殼（標題保證一致）

學員權限是「用課程標題對應」的，標題必須跟 Teachify 完全一致。用工具照 CSV 自動建好，就不會打錯字。先試跑看會建哪些（不寫入）：

node scripts/create-course-shells.mjs "你的CSV路徑"

沒問題後正式建立：

node scripts/create-course-shells.mjs "你的CSV路徑" --commit

它會依 CSV 算出的門數自動建好空殼（本例約 26 門，實際以工具印出的數字為準；標題完全正確、狀態為「未發佈」）。

2-2. 批次上傳影片到 Bunny

把影片檔放進一個資料夾（你的擺法「一個資料夾一門課」正好最適合；檔名不必精準，工具只拿它當「建議的章節名」）。先掃描看看（不上傳、不用金鑰）：

node scripts/bunny-upload.mjs "你的影片資料夾"

看 bunny-upload-plan.csv 抓到的檔對不對，然後正式上傳（可先加 --limit 3 傳 3 支測試）：

node scripts/bunny-upload.mjs "你的影片資料夾" --upload

完成給你 bunny-upload-result.csv（每支影片的 Bunny 網址）。

⏳ 兩個提醒

① 影片檔大、上傳要時間，工具可中斷後續傳（重跑自動略過已傳的），不怕斷線。
② 需要 Bunny「上傳用 API Key」（BUNNY_STREAM_API_KEY，在 Bunny → Stream → 影片庫 → API），跟播放防盜金鑰是不同的兩把。

2-3. 批次上傳教材簡報

章節裡的簡報/講義（.pptx、.pdf 等）不是放 Bunny，用另一支工具傳到 Supabase（不需 Bunny 金鑰）。放在同一個影片資料夾即可，它會自動只挑文件、略過影片和圖片：

node scripts/upload-materials.mjs "你的影片資料夾"             # 先掃描看 plan.csv
node scripts/upload-materials.mjs "你的影片資料夾" --upload   # 正式上傳（可中斷續傳）

完成給你 materials-upload-result.csv（每個教材的網址）。

2-4. 貼進章節、發佈課程

到後台 /admin，為每門課補上說明，並依兩張對照表把網址貼進各章節：

  • 影片：貼 bunny-upload-result.csv 的 embed_url 或 bunny_guid（兩種系統都認得）進「影片網址」。
  • 教材：貼 materials-upload-result.csv 的網址進章節「教材／附件」。

每門課補完後記得按「發佈」，課程才會對外顯示。

💡 這一步的手動部分

「哪支影片/教材屬於哪門課的哪一章」只有你知道，所以「貼進章節」這段是手動照對照表貼。工具已幫你把上傳和命名都做完，不會漏、不會錯傳，只剩貼上。

3

匯入學員與課程權限（自動）

656 位學員一次匯入，不用手打

第一步：只看 CSV（最安全，不連資料庫）。先確認人數與課程清單讀得對：

node scripts/import-students.mjs "你的CSV路徑" --preview

第二步：試跑（會連你的資料庫比對課程標題、但不寫入；此步需 .env.local 已設好）：

node scripts/import-students.mjs "你的CSV路徑"

它會告訴你課程標題「有幾種對上了、哪幾種還沒對上（打錯字或還沒建）」。全部對上後，正式匯入：

node scripts/import-students.mjs "你的CSV路徑" --commit

✅ 完成後

656 位學員都建好了，每個人也自動開通了他在 Teachify 買過的課。可以重複跑，不會重複建立。

4

寄「設定新密碼」信給全體學員（自動）

客戶點一下就能繼續用

⏳ 寄信前兩個前提（都要滿足才 --send）

① 寄件人網域：RESEND_FROM_EMAIL 必須是已驗證的自家網域（用你買的域名，例如網域是 myschool.com 就填 no-reply@myschool.com；作法見《開站手冊》步驟 4）。還在用沙盒地址的話工具會擋下。要先驗證網域
② 網址要先定案：信裡的「設定密碼」連結是用 .env.local 的 NEXTAUTH_URL 組出來的、效期 7 天。所以請先把 NEXTAUTH_URL 設成客戶最終會用的正式網址（https://bds.fu-notes.com）再 --send；否則連結會指到臨時網址，切換網域後可能失效。最穩的做法：把這步（--send）放到步驟 5 換好網域、確認新站能登入之後再做。

⚠️ 656 封不能「一次寄完」——會爆 Resend 每日上限

Resend 免費方案通常有每日約 100 封、每月約 3,000 封的上限（實際數字以你的 Resend 後台方案為準）。656 封一次送，超過當日上限後會大量失敗、約 550 位客戶收不到信卻沒人發現。工具已內建保護：偵測到寄信商上限會自動停、已寄成功者會記錄，隔天用同一指令即自動續寄。二選一：

  • （推薦）分批寄：用 --limit 每天寄一批，例如每天 --limit 100，連續幾天寄完。工具會自動記錄「已寄成功的人」，隔天用同一指令再跑就只補剩下的、不會重複寄。
  • 升級 Resend 付費方案後一次寄完（額度拉高）。

（更正舊說法：每封間隔 0.4 秒只避開「每秒速率」，不會避開「每日總量」上限。）

先寄一封測試信給自己看版面（測試信只是預覽版型，連結點了不會真的能設密碼）：

node scripts/send-invites.mjs "你的CSV路徑" --test 你的信箱@example.com

確認前提都滿足後，分批寄出（每天一批；沒加 --limit 就是一次全寄）：

node scripts/send-invites.mjs "你的CSV路徑" --send --limit 100

寄完會產生 send-invites-result.csv（每位 sent/failed），打開核對有沒有失敗的；有失敗就再跑同一指令會自動只補未成功者。學員收到信 → 點按鈕 → 設定新密碼 → 用原本 Email 登入，課程權限都在。

⏰ 什麼時候寄？請放到最後

兩個前提：① RESEND_FROM_EMAIL 是已驗證的自家網域；② 已完成步驟 5 換網域、NEXTAUTH_URL 已是正式網址且穩定。信裡連結用 NEXTAUTH_URL 組成、效期 7 天，所以務必等正式網址穩了才群發，否則連結會落在網域還沒生效的空窗期。

5

把網址切到新網站（安全換網域）

幾百位既有客戶要「幾乎無感」——照這個順序做，並先備好回滾

⚠️ 這步最怕客戶斷線，務必照順序、別跳

換網域＝把 bds.fu-notes.com 從指向 Teachify 改成指向 Netlify。做不好，切換當下客戶可能連不上或看到「不安全」。下面每一小步都是為了把斷線壓到最短、且萬一有問題能秒切回。

5-1. 切換前 1～2 天：把 TTL 調低

到網域管理處，把 bds.fu-notes.com 那筆記錄的 TTL 調到最低（例如 300 秒）。TTL 決定「全世界的快取多久更新一次」；先調低，正式切換才會在幾分鐘內生效（而不是等數小時～一天），回滾也才能快。

5-2. 先在 Netlify 加自訂網域（這時還不要改 DNS）

Netlify → Domain management → 把 bds.fu-notes.com 加為自訂網域。先加好，Netlify 才會開始準備 HTTPS 憑證，縮短之後「不安全」的空窗。它會給你待會要在 DNS 填的值。

5-3. 抄下目前的 DNS 設定（回滾用）

切換前，先把 bds.fu-notes.com 現在指向 Teachify 的那筆記錄（類型與值）截圖或抄下來。萬一切換後有問題，把它改回這個值就能秒切回 Teachify 止血。

5-4. 設好新站網址並重新部署

到 Netlify 環境變數把 NEXTAUTH_URL 改成 https://bds.fu-notes.com，然後務必到 Deploys → Trigger deploy → 選「Clear cache and deploy site」手動觸發一次（只改環境變數不會自動生效）。

5-5. 正式改 DNS 指向 Netlify

選離峰時段，把 bds.fu-notes.com 依 Netlify 給的值改指過去。因為 5-1 已降 TTL，通常幾分鐘生效。

5-6. 等 HTTPS 憑證就緒

回 Netlify Domain management，等狀態顯示憑證已簽發（出現 Netlify certificate / SSL 或綠色鎖頭）。然後用無痕視窗開 https://bds.fu-notes.com，確認網址列是鎖頭、不是「不安全」。

5-7. 在「正式網址」上煙霧測試

就在 https://bds.fu-notes.com（不是臨時網址）跑一遍關鍵路徑：登入、看課、下單走完金流看是否正確導回、觸發一次密碼重設信看連結網域對不對、點得開。全部過，才算切換成功。

🔙 回滾（萬一新站出問題）

把 bds.fu-notes.com 的 DNS 改回 5-3 抄下的 Teachify 值即可切回（因已降 TTL，幾分鐘生效）。所以——Teachify 在這段觀察期一定要保持付費、不要退租。

⛔ Teachify 什麼時候才能停？

務必等以下三件事全部達成才可退租/停付 Teachify（太早停，Teachify 上的影片與內容會被關、永久拿不回）：
① 該從 Teachify 拿的都拿齊了（見步驟 2 上方「必拿清單」）；② 新站在正式網址上完整驗收（登入/看課/金流）；③ 換網域後穩定運作數天、含尖峰、零客訴。

✅ 切換成功後，才做最後一步：寄設定密碼信

現在正式網址穩了，回到步驟 4 執行 --send。這樣 656 封信裡的連結都會指向已生效的正式網址。

※ 關於 --test：它只驗證「信寄得出去、版型正常」；測試信裡的連結點了不會真的能設密碼（那是預覽，未寫入 token），這是正常的。要確認「真的能重設密碼」，請在正式群發後，用一個真實學員帳號收到的正式信去點連結測試。

附錄

指令速查表（搬家當天照順序複製貼上）

📌 用之前先確認（第一次跑一定要看）

① 裝好 Node.js 並安裝套件。先到 nodejs.org 下載安裝 Node.js（選 LTS 版）。然後開終端機、切到 bds-web 資料夾，執行一次：

npm install

（這會安裝腳本用到的套件。沒做的話，一跑就會噴 Cannot find module 而失敗。）

② 在 bds-web 資料夾建立 .env.local，填「你自己」的鑰匙。把專案裡的 .env.example 複製一份、改名為 .env.local，填入你自己新建的 Supabase 專案金鑰（NEXT_PUBLIC_SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY），以及 NEXTAUTH_URL、Resend（RESEND_API_KEY、RESEND_FROM_EMAIL）、Bunny 的鑰匙。

⚠️ 千萬別直接沿用賣方交給你的舊 .env.local

裡面是賣方的舊鑰匙，會連到賣方的舊資料庫，把課程和 656 位學員灌錯地方。一定要換成你自己新專案的鑰匙。

③ 影片上傳要 Bunny 兩個值。步驟 2 的 bunny-upload.mjs 需要 BUNNY_STREAM_LIBRARY_ID 與 BUNNY_STREAM_API_KEY（後者在 Bunny → Stream → 影片庫 → API 分頁，和播放防盜金鑰不同），兩個都要填進 .env.local。

④ 路徑替換：把指令裡的 你的CSV路徑 換成實際位置，例如 "../BDS-students-2026-08-24.csv"。

⚠️ 幾個容易踩的小地雷

  • CSV 表頭要用英文：必須含 Email 與 Attended courses（大小寫沒關係、其餘欄選用）。Teachify 若匯出成中文表頭，先把這兩欄名改成英文再跑。
  • 課程標題不要含半形逗號 ,：工具用逗號分隔課程清單，標題含逗號會被切碎成怪標題。試跑時看印出的課程清單有沒有怪怪的半截標題。
  • 教材單檔上限 50MB：超過的簡報/檔案會被 upload-materials 略過（結果會標「略過」）。太大的先壓縮、拆檔，或放雲端後在後台貼連結。
▸

依序執行

每一步都「先試跑、再正式做」，確認數字對了才加 --commit / --upload / --send

① 建立 26 門課空殼（標題保證正確）

node scripts/create-course-shells.mjs "你的CSV路徑"            # 先試跑看清單
node scripts/create-course-shells.mjs "你的CSV路徑" --commit   # 正式建立

② 影片批次上傳 Bunny（→ 產生對照表）

node scripts/bunny-upload.mjs "你的影片資料夾"                 # 先掃描看 plan.csv
node scripts/bunny-upload.mjs "你的影片資料夾" --upload --limit 3   # 先傳 3 支測試
node scripts/bunny-upload.mjs "你的影片資料夾" --upload        # 全部上傳（可中斷續傳）

→ 依 bunny-upload-result.csv 到後台把影片網址貼進各課章節。

②-2 教材簡報批次上傳（.pptx/.pdf 等 → 傳 Supabase）

node scripts/upload-materials.mjs "你的影片資料夾"             # 先掃描看 plan.csv
node scripts/upload-materials.mjs "你的影片資料夾" --upload   # 全部上傳（可中斷續傳）

→ 依 materials-upload-result.csv 把教材網址貼進章節「教材／附件」欄位；補完內容後發佈課程。

③ 匯入 656 位學員 + 課程權限

node scripts/import-students.mjs "你的CSV路徑" --preview        # 只看 CSV（不連 DB）
node scripts/import-students.mjs "你的CSV路徑"                 # 試跑：確認「對不上 0 種」
node scripts/import-students.mjs "你的CSV路徑" --commit        # 正式匯入（對不上>0 會被擋下）

→ 試跑要顯示「對不上 0 種」才 --commit；匯入後照結果的驗收指引對帳。

④ 換網域（見上方步驟 5 的安全 SOP）

先降 TTL → Netlify 加網域 → 抄舊 DNS（回滾用）→ 設 NEXTAUTH_URL＋Trigger deploy → 改 DNS → 等憑證 → 正式網址煙霧測試。確認穩定前 Teachify 別停。

⑤ 最後才寄「設定新密碼」信（分批）

node scripts/send-invites.mjs "你的CSV路徑" --test 你的信箱          # 只驗證信寄得出、版型正常（連結是預覽、不會真的能設密碼）
node scripts/send-invites.mjs "你的CSV路徑" --send --limit 100     # 每天一批，隔天再跑即續傳（達上限會自動停）

→ 前提：網域已切好、NEXTAUTH_URL 已是正式網址、RESEND_FROM_EMAIL 是已驗證網域。寄完看 send-invites-result.csv 補失敗者。

✅ 順序邏輯（別跳）

先有課（①）→ 影片/教材就位（②）→ 灌人和權限（③）→ 換網域並驗收穩定（④）→ 最後才通知客戶（⑤）。寄信放最後，是因為信裡連結要用「已生效的正式網址」，否則客戶點開是壞的。
