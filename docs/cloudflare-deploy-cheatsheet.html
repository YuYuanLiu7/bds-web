Cloudflare 首次部署小抄

給工程師：把這個 Next.js（OpenNext）網站部署到 Cloudflare Workers。複製指令即可。搭配《開站手冊》步驟 6-B。

⚠️ 兩個一定要記住的雷（否則會失敗或收不到錢）

1. cf:deploy 不會自動 build → 一定先 cf:build 再 cf:deploy。

2. NEXT_PUBLIC_* 在 build 當下就寫死進前端（尤其 NEXT_PUBLIC_PAYUNI_UPP_URL）。本機 build 就要有 .env.local、且填正式金流端點，否則刷卡會靜默走 sandbox、收不到真錢。

💳 免費版部署不了：需開 Workers Paid（US$5/月）

Cloudflare Workers 免費版腳本上限 3 MiB，本站（完整 Next.js）壓縮後約 4～5 MiB 會超過、部署會失敗（錯誤 exceeded the size limit of 3 MiB）。請先在 Cloudflare 開 Workers Paid（約 US$5/月，上限 10 MiB） 再部署。

🔌 兩種做法的差別（先搞懂再選）

做法一（本機 CLI）：從你電腦上傳，不會連動 GitHub、不會自動部署；每次更新都要回電腦重跑 cf:build＋cf:deploy。

做法二（連 GitHub）：push 到 GitHub 就自動重建部署，較省事。

環境變數：填哪裡、填什麼

填在哪裡？

  • 做法一：把 NEXT_PUBLIC_ 開頭的填在本機 bds-web/.env.local（build 期要用）；伺服器端的值填在 Cloudflare 儀表板 → 你的 Worker → Settings → Variables and Secrets（執行期要用，敏感的選 Secret/Encrypt）。
  • 做法二：全部填在 Cloudflare 專案的變數設定；其中 NEXT_PUBLIC_ 與 NODE_VERSION 要放到「建置(Build)也讀得到」的一般變數（Plaintext），敏感的伺服器值設 Secret。

要填哪些？值哪裡來？（值＝你在《開站手冊》步驟 6-3「鑰匙收集表」填過的那些）

變數名稱值（從哪來）類型
NEXT_PUBLIC_SUPABASE_URLSupabase 專案網址一般
NEXT_PUBLIC_SUPABASE_ANON_KEYSupabase anon 公開金鑰一般

前置

  1. Node 22（20 以上）、已安裝 git。
  2. 程式碼已在你的 GitHub（開站手冊 6-1），且已把 repo clone 到本機。
  3. Supabase／PayUni／Bunny／Resend 的金鑰都已備妥（開站手冊步驟 2–5）。

做法一：本機 CLI 部署（最單純，推薦第一次用）

# 於 bds-web 資料夾
npm install

# 1) 建 .env.local（本機 build 要靠它把 NEXT_PUBLIC_* 編進前端）
#    複製 .env.example 後填入「正式」值，務必確認：
#    NEXT_PUBLIC_PAYUNI_UPP_URL = https://api.payuni.com.tw/api/upp  (正式，不是 sandbox)
cp .env.example .env.local
# 用編輯器把 .env.local 各值填好

# 2) 登入 Cloudflare（開瀏覽器授權）
npx wrangler login

# 3) 第一次 build + 部署（分兩步！）→ 完成後會印出 *.workers.dev 網址
npm run cf:build
npm run cf:deploy

# 4) 到 Cloudflare 儀表板 → 你的 Worker → Settings → Variables and Secrets
#    加入「伺服器端」變數（敏感值設 Secret）：
#    SUPABASE_SERVICE_ROLE_KEY, NEXTAUTH_SECRET, PAYUNI_MERID/HASH_KEY/HASH_IV,
#    RESEND_API_KEY/RESEND_FROM_EMAIL, BUNNY_STREAM_LIBRARY_ID/API_KEY, BUNNY_TOKEN_AUTH_KEY ...
#    NEXTAUTH_URL = 上一步拿到的 https://bds-web.<你的帳號>.workers.dev

# 5) 把 .env.local 的 NEXTAUTH_URL 也改成該 workers.dev，再 build+deploy 一次
npm run cf:build
npm run cf:deploy

nodejs_compat 不用自己設

wrangler.jsonc 已內含 nodejs_compat 旗標與 main=.open-next/worker.js、assets 綁定，部署會自動套用。

做法二：連 GitHub 自動部署（push 即上線）

  1. Cloudflare → Workers & Pages → Create → Import a repository，選你的倉庫。
  2. Build command：npx opennextjs-cloudflare build；Deploy command：npx wrangler deploy。
  3. 環境變數：照上面「環境變數：填哪裡、填什麼」那張表逐一新增（在該 Worker 的 Settings 變數設定）；NODE_VERSION=22 與 NEXT_PUBLIC_* 設「一般（plaintext）」讓 build 讀得到，敏感值設 Secret；NEXTAUTH_URL 先填 workers.dev。
  4. 之後 push 到 GitHub 自動重建；改 NEXT_PUBLIC_* 後到 Deployments 觸發一次重建。

綁自訂網域（測完再做）

  1. Worker → Settings → Domains & Routes 加你的網域（會自動處理 HTTPS 憑證）。
  2. 把 NEXTAUTH_URL（.env.local 與/或儀表板）改成正式網域 → 重新 build+deploy（做法一）或觸發重建（做法二）。
  3. 搬家情境：換網域前先降 DNS TTL、抄舊 DNS 供回滾，新站穩定前別停舊平台（見《搬家手冊》步驟 4）。

✅ 上線前最後驗收（務必做）

1. npm run verify（於 bds-web，需 .env.local）全綠。
2. 用真卡買一筆最便宜商品，確認「付款成功 → 自動開通 → 收到通知信」，並確認金流是打到正式端點（不是 sandbox），再退刷。
3. 登入、看片、後台各點一遍。

搭配《開站手冊》步驟 6-B 使用。環境變數清單見開站手冊步驟 6-3。
